# WHYTREE
## SoleMate — Why Tree 분석

> Rasmussen의 Work Domain Analysis에서 영감을 받은 수단-목적 연결 기법  
> - **Why Up:** "왜?"를 반복하며 제품의 본질로 올라간다  
> - **How Down:** "어떻게?"를 반복하며 구체적 구현으로 내려간다

---

## Part 1. Why Up — "왜 이 서비스를 만드는가?"

*아래(제품)에서 위(본질)로 올라가며 존재 이유를 탐색한다*

---

### L1 — 제품 (Product)

| 항목 | 내용 |
|------|------|
| 서비스명 | **SoleMate** |
| 정의 | 데이터 기반 개인화 러닝화 추천 서비스 |
| 핵심 기능 | 신체 조건 + 기록 + 대회 정보를 입력하면 AI가 최적 러닝화를 추천 |

---

### L2 — 기능적 이유 (Functional Reason)
> 왜 이 제품이 필요한가?

| 기능 | 설명 |
|------|------|
| 개인화 추천 | 발 모양·아치·폭·체중 등 신체 조건 기반 필터링 |
| 데이터 기반 분석 | 이커머스 리뷰 수천 건을 AI로 분석, 노이즈 제거 |
| 대회 최적화 | 국내 10대 대회 코스 특성(노면·지형·날씨)을 반영한 추천 |
| 기록 기반 매칭 | 현재 기록과 목표 기록에 맞는 카테고리(레이싱·트레이닝·완주) 분류 |

---

### L3 — 사용자 가치 (User Value)
> 왜 그 기능이 필요한가?

| 가치 | 설명 |
|------|------|
| 구매 실패 비용 절감 | 잘못된 선택으로 인한 금전적 손실 방지 (러닝화 평균 15만 원) |
| 부상 예방 | 내전·외전 미고려 러닝화 착용 → 무릎·발목 부상 위험 감소 |
| 기록 향상 가능성 | 코스·거리에 맞는 러닝화 선택 → 퍼포먼스 최적화 |
| 정보 탐색 시간 단축 | 카페·블로그·SNS를 헤매는 시간 제거 |

---

### L4 — 심리적 욕구 (Psychological Need)
> 왜 그 가치가 중요한가?

| 욕구 | 설명 |
|------|------|
| 러닝을 오래 즐기고 싶다 | 부상 없이 지속 가능한 러닝 라이프를 원한다 |
| 목표 대회를 완주하고 싶다 | 서울마라톤, 춘천마라톤 등 버킷리스트를 이루고 싶다 |
| 올바른 선택을 했다는 확신 | "이 신발이 나한테 맞는 게 맞아?" 라는 불안에서 벗어나고 싶다 |
| 돈을 현명하게 쓰고 싶다 | 비싼 신발을 샀는데 실패하고 싶지 않다 |

---

### L5 — 본질적 욕구 (Core Desire)
> 가장 근본적인 이유는 무엇인가?

> **"건강하고 활기찬 삶을 살고 싶다"**  
> 러닝은 나를 위한 시간.  
> 러닝화는 그 시간을 지켜주는 도구.  
> 올바른 러닝화 선택은 단순한 소비가 아니라 **건강한 삶에 대한 투자**다.

---

### Why Tree 구조 시각화

```
RunFit — 데이터 기반 러닝화 추천 (L1)
  └── 왜?
      ├── 개인화 추천 제공
      ├── 데이터 기반 리뷰 분석          (L2 — 기능적 이유)
      ├── 대회 코스 최적화
      └── 기록 기반 매칭
          └── 왜?
              ├── 구매 실패 비용 절감
              ├── 부상 예방                (L3 — 사용자 가치)
              ├── 기록 향상 가능성
              └── 정보 탐색 시간 단축
                  └── 왜?
                      ├── 러닝을 오래 즐기고 싶다
                      ├── 목표 대회를 완주하고 싶다    (L4 — 심리적 욕구)
                      ├── 올바른 선택의 확신
                      └── 현명한 소비를 하고 싶다
                          └── 왜?
                              └── 건강하고 활기찬 삶을 살고 싶다  (L5 — 본질)
                                  "러닝화는 건강한 삶에 대한 투자다"
```

### 핵심 수렴 인사이트

> L2의 4가지 기능이 L5의 단 하나의 본질로 수렴한다  
> **"사람들은 러닝화를 사는 게 아니라, 부상 없이 오래 달리는 삶을 산다"**  
> → 이것이 RunFit의 존재 이유이자 발표 오프닝 스토리의 핵심

## Part 2. How Down — "어떻게 만들 것인가?"

*위(목표)에서 아래(기술)로 내려가며 구현 경로를 탐색한다*

---

### L1 — 목표 (Goal)

| 항목 | 내용 |
|------|------|
| 최종 목표 | **건강한 러닝 라이프 지원** |
| 구체화 | 내 몸·기록·대회에 최적화된 러닝화를 데이터로 찾아주는 것 |

---

### L2 — 핵심 기능 (Core Features)
> 어떻게 목표를 달성할 것인가?

| 기능 | 설명 |
|------|------|
| 개인 프로파일 수집 | 신체 조건 + 러닝 조건 + 대회 정보 입력 |
| 다중 소스 데이터 분석 | 이커머스·유튜브 리뷰 크롤링 + AI 감성 분석 |
| AI 추천 엔진 | Claude API 기반 추천 + 자연어 이유 생성 |

---

### L3 — 서브 기능 (Sub-Features)
> 각 핵심 기능을 어떻게 구현할 것인가?

| 상위 기능 | 서브 기능 | 설명 |
|-----------|-----------|------|
| 개인 프로파일 수집 | 신체 조건 입력 폼 | 발 모양·폭·아치·체중·성별·나이 |
| 개인 프로파일 수집 | 러닝 조건 입력 폼 | 수준·환경·기록·예산·우선순위 |
| 개인 프로파일 수집 | 대회 선택 모듈 | 국내 10대 대회 + 목표기록 입력 |
| 데이터 분석 | 리뷰 크롤링 | 무신사·SSG·네이버·유튜브 수집 |
| 데이터 분석 | 감성 분석 | 발 타입별 긍·부정 패턴 추출 |
| AI 추천 엔진 | 발 타입 필터링 | 내전·외전·중립 카테고리 분류 |
| AI 추천 엔진 | 기록 기반 분류 | 레이싱·퍼포먼스·완주용 분류 |
| AI 추천 엔진 | 코스 특성 매칭 | 대회 코스 DB 참조 및 변수 반영 |

---

### L4 — 구현 방식 (Implementation Approach)
> 서브 기능을 어떻게 구현할 것인가?

| 서브 기능 | 구현 방식 | 비고 |
|-----------|-----------|------|
| 신체·러닝 조건 입력 | 단계별 온보딩 UI (스텝 폼) | 이탈률 최소화 |
| 대회 선택 | 10개 대회 카드 UI + JSON DB | 하드코딩으로 MVP 구현 |
| 리뷰 데이터 | 샘플 데이터 전처리 (MVP) | 실제 크롤링은 후속 개발 |
| 발 타입 필터 | 규칙 기반 로직 (if-else) | 명확한 기준 존재 |
| 추천 + 이유 생성 | Claude Sonnet API ⭐ | 핵심 데모 포인트 |
| 결과 화면 | 카드형 UI (1·2·3순위) | 비교 포인트 명시 |

---

### L5 — 기술 스택 (Tech Stack)
> 구현 방식을 어떤 기술로 실현할 것인가?

| 영역 | 기술 | 용도 |
|------|------|------|
| 프론트엔드 | React + TypeScript | 전체 UI 구현 |
| 스타일링 | Tailwind CSS | 반응형 디자인 |
| AI 추천 엔진 | Claude Sonnet API ⭐ | 추천 로직 + 자연어 생성 |
| 데이터 저장 | Firebase / Supabase | 사용자·입력 데이터 |
| 리뷰 데이터 | Python 크롤러 (후속) | 무신사·네이버 리뷰 수집 |
| 대회 DB | JSON 파일 | 10개 대회 코스 특성 |

---

### How Down 구조 시각화

```
건강한 러닝 라이프 지원 (L1)
  ├── 개인 프로파일 수집 (L2)
  │     ├── 신체 조건 입력 폼
  │     ├── 러닝 조건 입력 폼        (L3)
  │     └── 대회 선택 모듈
  │           ├── 스텝 온보딩 UI
  │           ├── 10개 대회 카드 UI   (L4)
  │           └── JSON DB
  │                 └── React + TypeScript / Firebase  (L5)
  │
  ├── 다중 소스 데이터 분석 (L2)
  │     ├── 리뷰 크롤링
  │     └── 감성 분석               (L3)
  │           ├── 샘플 데이터 (MVP)   (L4)
  │           └── Python 크롤러 (후속)
  │                 └── Firebase / Supabase            (L5)
  │
  └── AI 추천 엔진 (L2) ⭐ 핵심 데모
        ├── 발 타입 필터링
        ├── 기록 기반 분류           (L3)
        └── 코스 특성 매칭
              ├── 규칙 기반 로직
              └── Claude API 호출    (L4)
                    └── Claude Sonnet API              (L5)
```

### How Down 핵심 인사이트

> L3의 **"코스 특성 매칭 + 감성 분석"** 과 L5의 **"Claude Sonnet API"** 가 연결되는 라인이 가장 강력한 데모 포인트  
> 사용자 조건 입력 → Claude가 분석 → "이 러닝화가 당신에게 맞는 이유"를 자연어로 출력하는 흐름이 발표장 임팩트 최대

## Part 3. Why Tree × How Down 교차 인사이트

| Why (존재 이유) | How (구현 방법) | 연결 포인트 |
|----------------|----------------|------------|
| 부상 예방 (L3) | 발 타입 필터링 (L3) | 내전·외전 데이터 → 안정성 카테고리 매칭 |
| 구매 실패 비용 절감 (L3) | 리뷰 감성 분석 (L3) | 실패 후기 패턴 제거 → 신뢰도 높은 추천 |
| 목표 대회 완주 (L4) | 코스 특성 매칭 (L3) | 대회 DB → 노면·날씨 변수 반영 |
| 건강한 삶 (L5) | Claude Sonnet API (L5) | "당신에게 맞는 이유"를 언어로 전달 |
